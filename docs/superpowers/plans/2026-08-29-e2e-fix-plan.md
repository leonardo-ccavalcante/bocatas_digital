# Bocatas Digital — E2E fix plan (root causes)

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Expanded tasks live in [`2026-08-29-e2e-fix-plan/`](2026-08-29-e2e-fix-plan/) and use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every shipped feature reliable and frictionless for the people who actually use it — a volunteer at the comedor counter on a low-end Android, Sole and Espe coordinating familias, and the admins — by fixing the code-level root causes behind 260 verified defects rather than their symptoms.

**Architecture:** Each task is one root cause: the single defect whose fix removes every finding grouped under it. Fixes are surgical (Karpathy rules: minimum code, touch only what the defect requires, no speculative refactors, no flags, no compat shims) and strictly TDD (RED → GREEN → refactor). Bigger structural work a fix *reveals* is recorded as a follow-up issue, never smuggled into the task.

**Tech stack:** Vite + React + TypeScript strict · wouter · shadcn/ui · TanStack Query · XState (check-in only) · Express + tRPC · Zod · Supabase (Postgres + Storage + Realtime) · Vitest · Playwright.

## Execution notes

- **One root cause per branch and PR.** Tasks are independent unless a `Depends on` line says otherwise.

- **CI is the verdict.** Mirror the gates locally (`pnpm lint`, `pnpm check`, the touched Vitest files, `supabase db reset` + the types recipe for schema changes), push, then poll `gh pr checks <PR>`.

- **Migrations:** new versions must sort after `origin/main`'s newest prefix; SQL must be existence-tolerant; any `DROP`+`CREATE` of a `SECURITY DEFINER` function must end with `GRANT EXECUTE … TO service_role` (that omission *is* RC-02).

- **Out of scope:** OCR / LLM / vision extraction (`server/_core/llm*.ts`, `*-ocr.ts`, `ocr.ts`, `extractFromPhoto`, `llm-doctor`) — owned by a concurrent work stream.

- **Environment:** `pnpm test` does not load `.env` (`node --env-file=.env node_modules/vitest/vitest.mjs run <file>`); the server reads `.env`, not `.env.local`, and needs `SUPABASE_URL=http://127.0.0.1:54321` — without it the server silently falls back to `VITE_SUPABASE_URL` and every DB procedure 500s (this happened mid-review).
