# RC-10 — Reparto: resolve the family representative and the scanned QR via families.titular_id, falling back to the member heuristic

> Part of [2026-08-29 E2E fix plan](../2026-08-29-e2e-fix-plan.md). **REQUIRED SUB-SKILL:** use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Severity:** high · **Status at HEAD:** open · **Estimate:** 45 min · **Findings:** F182, F183

**Goal:** Make the reparto flow recognize the head of family (titular): the acta/Hoja de Firmas and counter roster must print the titular's name/DNI/phone (F182, route /programas/programa_familias?tab=repartos), and scanning the titular's QR at the counter must resolve to the family's assignment instead of "Persona no encontrada en ninguna familia del programa" (F183, Cierre por día → Escanear QR).

**Rationale:** families.create (server/routers/families/crud.ts:224-231 + _shared.ts mirrorMembersToTable:165-191) writes ONLY input.miembros to familia_miembros (rol "dependent", Spanish relaciones like "hijo_a") — the titular exists only as families.titular_id. But both resolution sites read exclusively familia_miembros: (a) reparto-helpers.ts resolveRepresentatives (:53-97) ranks member rows via pickRepresentatives, whose relacion==="parent" preference never matches wizard vocabulary, so the acta names a child or nobody ("Sin titular"); (b) rounds-closeout.ts resolveAssignment (:108-117) maps person→family only through familia_miembros.person_id, so the titular's QR returns not_in_program. The stale comment "families.titular_id is empty in prod" (reparto-helpers.ts:5) is refuted by the local DB — wizard families all have titular_id. Fixing the two readers (titular_id wins, member heuristic as fallback) repairs every consumer at once: buildRoundActa (acta de citación/final via rounds-documents.ts), getSlotRoster (counter roster + firma signer), rounds-ocr.ts, and resolveAssignment. No schema change needed.

export async function resolveRepresentatives(
  // eslint-disable-next-line @typescript-eslint/no-explicit-any
  db: SupabaseClient<any>,
  familyIds: string[],
): Promise<Map<string, Representative>> {
  const result = new Map<string, Representative>();
  if (familyIds.length === 0) return result;

  const [famRes, memRes] = await Promise.all([
    db.from("families").select("id, titular_id").in("id", familyIds).is("deleted_at", null),
    db
      .from("familia_miembros")
      .select("familia_id, relacion, created_at, person_id")
      .in("familia_id", familyIds)
      .is("deleted_at", null),
  ]);

  // families.titular_id wins; the member heuristic covers families without one.
  const reps = pickRepresentatives((memRes.data ?? []) as MemberRow[]);
  const personByFamily = new Map<string, string | null>();
  for (const f of famRes.data ?? []) if (f.titular_id) personByFamily.set(f.id, f.titular_id);
  for (const [fid, m] of reps) if (!personByFamily.has(fid)) personByFamily.set(fid, m.person_id);

  const personIds = [...new Set([...personByFamily.values()].filter((x): x is string => !!x))];
  const persons = new Map<string, Omit<Representative, "person_id">>();
  if (personIds.length > 0) {
    const { data: prows } = await db
      .from("persons")
      .select("id, nombre, apellidos, numero_documento, telefono")
      .in("id", personIds);
    for (const p of prows ?? []) {
      persons.set(p.id, {
        nombre: p.nombre ?? null,
        apellidos: p.apellidos ?? null,
        numero_documento: p.numero_documento ?? null,
        telefono: p.telefono ?? null,
      });
    }
  }

  for (const [familyId, personId] of personByFamily) {
    const ident = personId ? persons.get(personId) : undefined;
    result.set(familyId, {
      person_id: personId,
      nombre: ident?.nombre ?? null,
      apellidos: ident?.apellidos ?? null,
      numero_documento: ident?.numero_documento ?? null,
      telefono: ident?.telefono ?? null,
    });
  }
  return result;
}
