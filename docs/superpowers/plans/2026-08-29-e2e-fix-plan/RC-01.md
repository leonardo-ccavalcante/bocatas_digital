# RC-01 — Accept empty optional form fields end-to-end: persons wizard, families intake, announcements form (client/server Zod drift)

> Part of [2026-08-29 E2E fix plan](../2026-08-29-e2e-fix-plan.md). **REQUIRED SUB-SKILL:** use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Severity:** critical · **Status at HEAD:** open · **Estimate:** 150 min · **Findings:** F024, F047, F250, F181, F058, F116, F158, F190, F001, F106, F228

**Goal:** Make the three core creation flows submit successfully when optional fields are left blank (the common case): /personas/nueva person registration (F024, F047, F250, F181 — every registration with a blank 'Llegada a España' 400s; North-Star flow), /familias/nueva intake (F158, F190 — cannot register a family without a persona autorizada, forcing volunteers to store fake autorizado=true data), and /admin/novedades announcement creation (F001, F106, F228 — no path through the form succeeds at all). Also close the phase-2/3 validation gap and the 1800-birth-year hole in the wizard (F058) and add drift-guard tests pinning client output ⊆ server input (F116, ADR-0001).

**Rationale:** Root cause: every server router hand-mirrors its client Zod schema instead of importing it, and the copies disagree on empty-string handling. An untouched HTML input registered with react-hook-form submits "" (never undefined). (a) persons: server/routers/persons/_shared.ts:45 fecha_llegada_espana has no ''-branch (email:47 / codigo_postal:50 do), and the client's ''→null transform (personCreate.ts:61) never runs because _useSubmit.ts:52 posts raw args.getValues(); PHASE_FIELDS (RegistrationWizard/index.tsx:67-71) is empty for phases 2-3 so errors surface only as a raw-JSON 400 toast. (b) families: server crud.ts:163 persona_recoge z.string().min(1) vs client optional/nullable, and IntakeWizard/index.tsx:103 always sends ''. (c) announcements: client FormSchema (AdminNovedades/_shared.ts:12-14) rejects '' for the date fields silently (no error rendered) and the server wants fecha_fin as ISO datetime while the form emits YYYY-MM-DD. The fix keeps each schema where it lives (full unification is the follow-up) but makes empty-optional semantics identical, makes the client actually submit parsed output, and pins the contract with cross-schema tests so the drift cannot silently return. persons/crud.ts str() already coerces ''→null after validation, and DB columns (families.persona_recoge, announcements.published_at/expires_at/fecha_fin) are already nullable — no migration needed.
